## Before We Write a Single Tag — What Is HTML Really?

HTML stands for **HyperText Markup Language**. Let's break that down:

- **HyperText** — text that links to other text. This is what makes the web a *web*.
- **Markup** — you're not writing logic or instructions. You're *annotating* content to tell the browser what each piece of content *is*.
- **Language** — it has rules (syntax), and the browser enforces them.

**The key mental model:** HTML is not a programming language. You don't write algorithms. You write *descriptions*. You're answering one question over and over:

> *"What kind of content is this?"*

A heading? A paragraph? A navigation menu? A table of data? HTML gives you a specific tag for each answer. The browser then uses those answers to render, index, and make your content accessible.

## 1. The HTML5 Document — Your Page's Contract with the Browser

Every HTML page is a structured document. Think of it like a formal letter: there's a specific format the browser expects, and if you skip parts, it has to guess — and its guess may be wrong.

```html
<!DOCTYPE html>
<html lang="en" dir="ltr">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <meta name="description" content="Techium is a digital agency">
    <title>Homepage - Techium</title>
    <link rel="icon" type="image/x-icon" href="./favicon.ico">
  </head>
  <body>
    <!-- Your visible content goes here -->
  </body>
</html>
```

### The Two Zones: `<head>` vs `<body>`

| Zone | Who uses it? | What goes inside? |
|---|---|---|
| `<head>` | Browser & search engines | Metadata, settings, page title |
| `<body>` | The user | Everything they see and interact with |

Nothing inside `<head>` is visible on the page. It's configuration, not content.

### Breaking Down Each Line

**`<!DOCTYPE html>`**
This is not a tag — it's a *declaration*. It tells the browser: "Parse this file as HTML5, not as HTML4 or XHTML." If you forget it, the browser enters "quirks mode" and tries to emulate old, inconsistent behavior. Always include it. Always put it first.

**`<html lang="en" dir="ltr">`**
The root element that wraps everything. The `lang` attribute tells the browser (and screen readers) what language the content is written in. `dir="ltr"` sets text direction to left-to-right. This matters for Arabic or Hebrew sites where `dir="rtl"` would be used.

**`<meta charset="utf-8">`**
Defines the *character encoding* — the system that maps bytes to characters. UTF-8 covers virtually every character and symbol from every human language. Without this, special characters like `é`, `ñ`, `©`, or emoji may display as garbage. **Always put this as the first tag inside `<head>`** — browsers need to know the encoding before reading anything else.

**`<meta name="viewport" content="width=device-width, initial-scale=1.0">`**
Without this, mobile browsers shrink your page down to desktop size by default, making text tiny and unreadable. This tag tells the browser: "Match your width to the device's actual screen width and don't zoom out."

**`<meta name="description" content="...">`**
This text appears under your page title in Google search results. It doesn't affect ranking directly, but it affects whether users click your link. Keep it under 160 characters.

**`<title>`**
Appears in the browser tab, bookmarks, and search engine results. Be specific — "Homepage" alone is a bad title. "Homepage - Techium" is better.

## 2. Semantic HTML — Writing Code That Means Something

### The Problem with `<div>` Soup

Before HTML5, developers built entire page layouts using only `<div>` tags. The result looked like this:

```html
<!-- Old approach — meaningless to anyone but the author -->
<div id="top-bar">
  <div id="logo">...</div>
  <div id="menu">...</div>
</div>
<div id="content">
  <div class="post">...</div>
</div>
<div id="bottom">...</div>
```

A browser can render this just fine. But a screen reader, a search engine crawler, or another developer reading your code has no idea what any of these `<div>`s *mean*. Is `#top-bar` a header? A navigation? An advertisement?

### The HTML5 Solution: Tags That Describe Intent

HTML5 introduced **semantic elements** — tags whose *name* communicates what the content is:

```html
<header>
  <!-- Site logo, site title, and/or main navigation -->
  <!-- One per page (or one per <article> or <section>) -->
</header>

<nav>
  <!-- Navigation menus ONLY — not every group of links qualifies -->
  <!-- Use for major navigation blocks -->
</nav>

<main>
  <!-- The central, unique content of this specific page -->
  <!-- There should be exactly ONE <main> per page -->
</main>

<section>
  <!-- A thematically grouped block of content -->
  <!-- Should almost always have a heading inside it -->
</section>

<article>
  <!-- A self-contained piece of content that makes sense on its own -->
  <!-- Think: blog post, news story, comment, product card -->
  <!-- Could be extracted and published elsewhere independently -->
</article>

<aside>
  <!-- Content tangentially related to the main content -->
  <!-- Sidebars, pull quotes, related links, ads -->
</aside>

<footer>
  <!-- Closing information: copyright, contact links, legal -->
  <!-- Can appear inside <article> or <section> too, not just the page -->
</footer>
```

### Why This Matters — The Three Beneficiaries

1. **Screen readers** — software used by visually impaired users reads semantic tags to announce page structure. "Navigation landmark," "Main content," "Article." Without semantics, everything is just text.

2. **Search engines** — Google gives more weight to text inside `<article>` and `<h1>` than to text inside a random `<div>`. Semantic HTML is good SEO.

3. **Your teammates (and future you)** — Semantic code is self-documenting. `<nav>` tells you immediately what it contains. `<div class="nav-thingy">` does not.

> **Rule of thumb:** If you're reaching for a `<div>`, ask yourself — "Is there a semantic tag that describes what this content actually *is*?" If yes, use it. Only use `<div>` when you need a generic container for layout or styling with no semantic meaning.

## 3. Headings — Your Page's Outline

Think of headings as the table of contents for your page. If you extracted only your headings, they should form a logical, readable outline of your content.

```html
<h1>Techium — Digital Agency</h1>       <!-- Page title. One per page. -->
  <h2>Our Services</h2>                 <!-- Major section -->
    <h3>Web Design</h3>                 <!-- Subsection of Services -->
    <h3>Mobile Development</h3>         <!-- Another subsection -->
  <h2>About Us</h2>                     <!-- Next major section -->
    <h3>Our Team</h3>                   <!-- Subsection of About -->
      <h4>Lead Developer</h4>           <!-- Sub-subsection -->
```

### The Rules — and the Reasoning Behind Them

**Only one `<h1>` per page.**
The `<h1>` represents the single most important topic on the page. If everything is equally important, nothing is. Search engines treat `<h1>` as the definitive answer to "what is this page about?"

**Don't skip heading levels.**
Going from `<h2>` to `<h4>` is like jumping from Chapter 2 to Section 4.1 with no Chapter 3 in between. Screen readers and crawlers interpret heading levels as a hierarchy. Gaps break that hierarchy.

**Headings describe structure, not style.**
If you want big text, use CSS. Do not use `<h3>` because you want medium-sized text. Use `<h3>` because the content is a third-level section. Style is CSS's job. Structure is HTML's job.

## 4. Organizing Content with Lists

Lists aren't just bullet points. Each list type carries semantic meaning.

### Unordered List `<ul>` — Order Doesn't Matter

Use when items are a collection where sequence is irrelevant.

```html
<!-- Services offered — no priority implied between them -->
<ul>
  <li>Web Design</li>
  <li>Mobile Development</li>
  <li>SEO Consulting</li>
</ul>
```

### Ordered List `<ol>` — Order Is Part of the Meaning

Use when sequence matters — steps, rankings, instructions.

```html
<!-- A process where step 1 must happen before step 2 -->
<ol>
  <li>Plan your content and structure</li>
  <li>Write the HTML markup</li>
  <li>Add styling with CSS</li>
  <li>Test across browsers</li>
  <li>Deploy to production</li>
</ol>
```

### Definition List `<dl>` — Terms and Their Descriptions

Underused and underappreciated. Perfect for glossaries, FAQs, or metadata pairs (label: value).

```html
<dl>
  <dt>HTML</dt>
  <dd>HyperText Markup Language — defines the structure and content of web pages</dd>

  <dt>CSS</dt>
  <dd>Cascading Style Sheets — controls the visual presentation of HTML</dd>

  <dt>JavaScript</dt>
  <dd>A programming language that adds interactivity and behavior to web pages</dd>
</dl>
```

## 5. Inline Text Elements — Giving Words Meaning

These elements live *inside* paragraphs and other block elements. Each one carries a specific semantic purpose.

```html
<p>
  This is a paragraph. Inside it, we can <em>emphasize something</em>
  to indicate stress or importance in speech. We can mark text as
  <strong>critically important</strong> when it's something the reader
  must not miss. We can reference <code>function_name()</code> inline
  when discussing code, or use <mark>highlighted text</mark> to draw
  attention to a specific passage.
</p>

<!-- <em>   — Emphasis (semantic stress, like italics in speech) -->
<!-- <strong>— Strong importance (not just bold, it means "this matters") -->
<!-- <code>  — Inline code or technical terms -->
<!-- <mark>  — Highlighted/relevant text in context -->
<!-- <small> — Fine print, legal disclaimers, captions -->
<!-- <span>  — Generic inline container (no semantics — like <div> but inline) -->
```

> **`<em>` vs `<i>` and `<strong>` vs `<b>`**
> `<i>` and `<b>` are purely visual — italic and bold. `<em>` and `<strong>` carry *semantic meaning*. A screen reader will stress `<em>` content when reading aloud. Use the semantic versions unless you have a specific stylistic reason for the visual ones.

## 6. Adding Media — Images, Video, and Audio

### Images

The `<img>` tag is a **void element** — it has no closing tag because it has no content to wrap. It pulls in an external resource.

```html
<!-- A complete, correct image element -->
<img
  src="images/team-photo.jpg"
  alt="Five developers collaborating around a whiteboard"
  width="800"
  height="500"
  loading="lazy">
```

**Every attribute explained:**

**`src`** — The path to the image file. This can be:
- Relative: `images/photo.jpg` (relative to the current HTML file)
- Absolute: `https://example.com/photo.jpg` (full URL)

**`alt`** — Alternative text. This is not optional for meaningful images. It serves three purposes:
1. Screen readers read it aloud to visually impaired users
2. Browsers display it when the image fails to load
3. Search engines use it to understand image content

Write `alt` text as if you're describing the image to someone on the phone. For a purely decorative image (a separator line, background pattern), use `alt=""` — an empty alt tells screen readers to skip it entirely.

**`width` and `height`** — Declare these in HTML even if you resize with CSS. Why? The browser needs to know the image's *aspect ratio* before the image loads, so it can reserve the correct amount of space. Without them, the page "jumps" as images pop in — this is called **Cumulative Layout Shift** and it degrades user experience.

**`loading="lazy"`** — The browser only fetches this image when the user scrolls near it. Use this for images that appear below the fold (not immediately visible). For the main hero image at the top of the page, use `loading="eager"` (the default) so it loads immediately.

```html
<!-- Bad: no alt, no dimensions, no lazy loading -->
<img src="photo.jpg" alt="image">

<!-- Good: descriptive, accessible, performance-aware -->
<img
  src="images/product-hero.jpg"
  alt="Screenshot of the Techium dashboard showing analytics data"
  width="1200"
  height="675"
  loading="lazy">
```

#### Responsive Images with `<picture>`

Sometimes you want to serve a different image depending on screen size — a smaller file for mobile, a larger one for desktop:

```html
<picture>
  <!-- Condition checked first: screens 800px or wider get the large image -->
  <source media="(min-width: 800px)" srcset="hero-large.jpg">

  <!-- Screens 400px or wider get the medium image -->
  <source media="(min-width: 400px)" srcset="hero-medium.jpg">

  <!-- Fallback: all other browsers, or if no source matches -->
  <img src="hero-small.jpg" alt="Techium agency team in the office">
</picture>
```

The browser evaluates `<source>` conditions top-to-bottom and uses the first one that matches. The `<img>` at the bottom is the required fallback — it also provides the `alt` text for the whole `<picture>` element.

### Video

The `<video>` element provides native playback. Always offer multiple formats because browser support varies.

```html
<video
  controls
  poster="video-thumbnail.jpg"
  width="720"
  height="405"
  preload="metadata">

  <!-- Browser picks the first format it supports -->
  <source src="intro.mp4"  type="video/mp4">
  <source src="intro.webm" type="video/webm">

  <!-- Subtitles for accessibility -->
  <track kind="subtitles" src="subtitles-en.vtt" srclang="en" label="English">

  <!-- Fallback message for very old browsers -->
  <p>Your browser doesn't support HTML5 video.
     <a href="intro.mp4">Download the video instead.</a>
  </p>
</video>
```

**Key attributes:**

| Attribute | What it does |
|---|---|
| `controls` | Shows the play/pause/volume UI |
| `poster` | Image shown before the user presses play |
| `preload="metadata"` | Loads only the duration and dimensions, not the full file |
| `preload="none"` | Loads nothing until the user presses play |
| `loop` | Restarts automatically when finished |
| `muted` | Starts without sound — required for `autoplay` to work in most browsers |
| `autoplay muted` | Plays automatically (sound off) — use sparingly, it's often annoying |

> **Why multiple `<source>` tags?** MP4 (H.264) works everywhere. WebM is more efficient but has slightly less support. Listing both ensures the widest compatibility while serving the best format when possible.

---

### Audio

Works exactly like `<video>`, without the visual track.

```html
<audio controls preload="none">
  <source src="podcast-ep1.mp3" type="audio/mpeg">
  <source src="podcast-ep1.ogg" type="audio/ogg">
  <p>Your browser doesn't support HTML5 audio.
     <a href="podcast-ep1.mp3">Download the episode.</a>
  </p>
</audio>
```

> For long audio files (podcasts, music), `preload="none"` is the right call — you don't want the browser downloading a 45-minute episode before the user even clicks play.

## 7. Tables — For Data, Not Layout

Tables exist for one purpose: **displaying tabular data** — information that has a logical row-column relationship.

**Use a table when:** you're displaying a spreadsheet, schedule, comparison chart, or any data where rows and columns carry meaning.

**Never use a table when:** you're trying to arrange your page layout. This was a 1990s hack. CSS Flexbox and Grid replaced it completely.

```html
<table>
  <caption>Q1 2024 Revenue Report</caption>   <!-- Accessible title for the table -->

  <thead>                                      <!-- Column header row(s) -->
    <tr>
      <th scope="col">Month</th>
      <th scope="col">Revenue</th>
      <th scope="col">Expenses</th>
      <th scope="col">Net Profit</th>
    </tr>
  </thead>

  <tbody>                                      <!-- Data rows -->
    <tr>
      <th scope="row">January</th>             <!-- Row header -->
      <td>$15,000</td>
      <td>$8,000</td>
      <td>$7,000</td>
    </tr>
    <tr>
      <th scope="row">February</th>
      <td>$18,000</td>
      <td>$9,000</td>
      <td>$9,000</td>
    </tr>
  </tbody>

  <tfoot>                                      <!-- Summary/totals row(s) -->
    <tr>
      <th scope="row">Total</th>
      <td>$33,000</td>
      <td>$17,000</td>
      <td>$16,000</td>
    </tr>
  </tfoot>
</table>
```

### Why `scope` on `<th>` Matters

`scope="col"` tells screen readers: "This header applies to all cells *below* it in this column."
`scope="row"` tells screen readers: "This header applies to all cells *to the right* in this row."

Without `scope`, a screen reader reading a data cell (`<td>`) can't tell you *what* that cell represents. With `scope`, it can say: "January, Revenue: $15,000" — context and data together.

### Spanning Cells

```html
<!-- Merge two columns into one -->
<td colspan="2">Covers two columns</td>

<!-- Merge two rows into one -->
<td rowspan="2">Covers two rows</td>
```

## 8. Links — How the Web Connects

The `<a>` (anchor) tag is what makes hypertext *hyper*. Every link is a `<a>` element with an `href` attribute pointing to a destination.

### The Four Types of Link Destinations

**1. Anchor Links (same page)**
```html
<!-- The link -->
<a href="#services">Jump to Services</a>

<!-- The target — must have a matching id -->
<section id="services">
  <h2>Our Services</h2>
</section>
```

**2. Relative Links (same website, different page)**
```html
<!-- Same folder -->
<a href="about.html">About Us</a>

<!-- Subfolder -->
<a href="pages/contact.html">Contact</a>

<!-- Go up one level -->
<a href="../index.html">Home</a>
```

**3. Absolute Links (external website)**
```html
<!-- Always use target="_blank" with rel="noopener noreferrer" for external links -->
<a href="https://www.github.com" target="_blank" rel="noopener noreferrer">
  View on GitHub
</a>
```

> **Why `rel="noopener noreferrer"`?**
> When you open a link in a new tab (`target="_blank"`), the new page gains a JavaScript reference to your original page via `window.opener`. A malicious site could use this to redirect your original tab. `noopener` breaks that reference. `noreferrer` also prevents passing your page URL to the destination. Always include both on external links.

**4. Special Protocol Links**
```html
<!-- Email — opens the user's mail client -->
<a href="mailto:hello@techium.com">Email Us</a>

<!-- Phone — tappable on mobile devices -->
<a href="tel:+17875551234">Call Us</a>

<!-- Download — forces download instead of navigation -->
<a href="brochure.pdf" download="Techium-Brochure-2024.pdf">Download Brochure</a>
```

### Building Accessible Navigation

Navigation should always be a `<nav>` containing a `<ul>` of links. This lets screen readers announce "Navigation, list of 4 items."

```html
<nav aria-label="Main navigation">
  <ul>
    <li><a href="index.html" aria-current="page">Home</a></li>
    <li><a href="about.html">About</a></li>
    <li><a href="services.html">Services</a></li>
    <li><a href="contact.html">Contact</a></li>
  </ul>
</nav>
```

`aria-current="page"` tells screen readers which link represents the current page. CSS can then use `[aria-current="page"]` to style the active link.

## 9. Embedding External Content with `<iframe>`

An `<iframe>` (inline frame) embeds another web page inside your page. Common uses: YouTube videos, Google Maps, social media widgets.

```html
<iframe
  src="https://www.youtube.com/embed/VIDEO_ID_HERE"
  width="560"
  height="315"
  title="Introduction to HTML — Holberton School"
  allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture"
  allowfullscreen
  loading="lazy">
</iframe>
```

**Important attributes:**

**`src`** — Must be the *embed* URL, not the regular watch URL.
- YouTube watch URL: `https://www.youtube.com/watch?v=VIDEO_ID`
- YouTube embed URL: `https://www.youtube.com/embed/VIDEO_ID`

**`title`** — Required for accessibility. Screen readers read this to describe what the iframe contains.

**`allow`** — A permissions policy controlling what the embedded content can access. Only grant what the embedded content actually needs.

**`loading="lazy"`** — Defers loading until the user scrolls near the iframe. Essential for pages with multiple embeds.

### Security: The `sandbox` Attribute

When embedding third-party or untrusted content, restrict what it can do:

```html
<iframe
  src="user-submitted-widget.html"
  title="User Widget"
  sandbox="allow-scripts">
  <!-- Without sandbox, the embedded page inherits all your page's permissions -->
  <!-- With sandbox, everything is blocked except what you explicitly allow -->
  <!-- allow-scripts: JavaScript runs, but can't access parent page -->
  <!-- allow-same-origin: can access cookies and localStorage -->
  <!-- allow-forms: forms can submit -->
</iframe>
```

> **Default behavior without `sandbox`:** The embedded page can run JavaScript that interacts with your page, submit forms, open popups, and more. Always sandbox untrusted content.

## 10. Best Practices — Writing Code That Lasts

### Validate Your HTML

The browser is forgiving — it will render broken HTML. But "works in my browser" isn't the same as "correct HTML." Invalid HTML behaves unpredictably across different browsers and tools.

Use the **W3C Validator**: [https://validator.w3.org/](https://validator.w3.org/)

Paste your code or enter your URL. Fix every error and warning before you ship.

### Comment Your Structure

```html
<!-- ==================== HEADER ==================== -->
<header>
  <!-- Logo -->
  <a href="index.html">
    <img src="images/logo.svg" alt="Techium logo" width="120" height="40">
  </a>

  <!-- Main navigation -->
  <nav aria-label="Main navigation">
    <ul>
      <li><a href="index.html" aria-current="page">Home</a></li>
      <li><a href="about.html">About</a></li>
    </ul>
  </nav>
</header>
<!-- ==================== END HEADER ==================== -->
```

### Accessibility Quick Checklist

Before calling any page "done," verify:

- [ ] `<html lang="...">` is set correctly
- [ ] Heading levels form a logical hierarchy with no gaps
- [ ] Every meaningful image has descriptive `alt` text
- [ ] Every decorative image has `alt=""`
- [ ] Every `<iframe>` has a `title` attribute
- [ ] Every `<table>` has `<caption>` and proper `scope` on headers
- [ ] Navigation is inside `<nav>` with `aria-label`
- [ ] External links have `rel="noopener noreferrer"`
- [ ] The page makes sense when read without CSS (structure alone carries meaning)

## 11. Putting It All Together

Here is a complete, correct, semantic HTML5 page integrating everything from this lecture:

```html
<!DOCTYPE html>
<html lang="en" dir="ltr">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <meta name="description" content="Techium builds modern digital experiences for growing businesses.">
    <title>Homepage — Techium Digital Agency</title>
    <link rel="icon" type="image/png" href="./favicon.png">
  </head>
  <body>

    <!-- HEADER: Logo + Main Navigation -->
    <header>
      <a href="index.html">
        <img src="images/logo.svg" alt="Techium" width="140" height="45">
      </a>
      <nav aria-label="Main navigation">
        <ul>
          <li><a href="index.html" aria-current="page">Home</a></li>
          <li><a href="about.html">About</a></li>
          <li><a href="services.html">Services</a></li>
          <li><a href="contact.html">Contact</a></li>
        </ul>
      </nav>
    </header>

    <!-- MAIN: Unique content for this page -->
    <main>

      <!-- Hero Section -->
      <section aria-labelledby="hero-heading">
        <h1 id="hero-heading">We Build Digital Experiences That Drive Growth</h1>
        <p>
          Techium is a full-service digital agency specializing in web design,
          mobile development, and search engine optimization.
        </p>
        <a href="services.html">Explore Our Services</a>
      </section>

      <!-- Services Section -->
      <section aria-labelledby="services-heading">
        <h2 id="services-heading">What We Do</h2>

        <article>
          <h3>Web Design</h3>
          <p>Beautiful, responsive websites built for performance and usability.</p>
        </article>

        <article>
          <h3>Mobile Development</h3>
          <p>Native and cross-platform apps that users love to use.</p>
        </article>

        <article>
          <h3>SEO Consulting</h3>
          <p>Data-driven strategies to increase your organic search visibility.</p>
        </article>
      </section>

      <!-- Team Photo Section -->
      <section aria-labelledby="team-heading">
        <h2 id="team-heading">Our Team</h2>
        <img
          src="images/team-2024.jpg"
          alt="The Techium team of eight developers and designers gathered in the office"
          width="960"
          height="540"
          loading="lazy">
        <p>A diverse team of designers, engineers, and strategists.</p>
      </section>

    </main>

    <!-- ASIDE: Supplemental info, not main content -->
    <aside aria-label="Client testimonials">
      <h2>What Clients Say</h2>
      <blockquote>
        <p>"Techium transformed our online presence completely."</p>
        <cite>— Maria Torres, CEO of LaunchPad PR</cite>
      </blockquote>
    </aside>

    <!-- FOOTER: Closing info -->
    <footer>
      <p>&copy; 2024 Techium. All rights reserved.</p>
      <nav aria-label="Footer navigation">
        <ul>
          <li><a href="privacy.html">Privacy Policy</a></li>
          <li><a href="mailto:hello@techium.com">Contact Us</a></li>
        </ul>
      </nav>
    </footer>

  </body>
</html>
```
