## 0. What Is JavaScript, Really?

You've written HTML (structure) and CSS (presentation). JavaScript is the third layer: **behavior**.

```
HTML        →  What is on the page
CSS         →  What it looks like
JavaScript  →  What it does
```

Without JavaScript: a webpage is a static document. It displays content. That's it.

With JavaScript: the page can respond to user actions, update content without reloading, validate forms before submission, fetch new data from a server, and change its own HTML and CSS dynamically.

JavaScript runs **inside the browser**. When you load a page, the browser downloads the HTML, CSS, and JavaScript files — then *executes* the JavaScript. This is different from languages like Python or C, which you run from a terminal. JS runs where the user is.

```
User opens page
  → browser downloads HTML, CSS, JS
  → browser parses and renders HTML + CSS (page appears)
  → browser executes JavaScript (page becomes interactive)
```

### JavaScript also runs on the server (Node.js)

The same language you use in the browser runs on servers via Node.js. This is why JavaScript is one of the few languages where you can write both the front-end (what users see) and back-end (server logic) in the same language.

## 1. Where to Write and Run JavaScript

### Option A: The Browser Console (Use This to Experiment)

Every browser has a built-in JavaScript interpreter. No setup needed.

1. Open any webpage in Chrome or Firefox
2. Press `F12` (or right-click → Inspect) → click the **Console** tab
3. Type any JavaScript — it runs immediately

This is your scratchpad. Any time you want to quickly test a piece of code, use the console.

### Option B: External JavaScript File (Use This for Projects)

```html
<!-- In your HTML file, at the END of <body> -->
<body>
  <!-- all your HTML content -->

  <script src="script.js"></script>
  <!--
    Loading JS at the END of body ensures the HTML is fully
    parsed before JavaScript tries to interact with it.
    If you load JS in <head>, it runs before the HTML exists —
    and querySelector("h1") returns null because h1 doesn't exist yet.
    Position matters.
  -->
</body>
```

```javascript
// script.js
console.log("JavaScript is connected and running.");
```

### Option C: Inline `<script>` Tag (Avoid for Anything Real)

```html
<script>
  console.log("Inline scripts mix behavior with structure.");
  // Fine for demos. Not for real projects.
</script>
```

### `console.log()` — Your Primary Debugging Tool

`console.log()` prints output to the browser's DevTools console. It doesn't show anything on the webpage — it talks to *you*, the developer.

```javascript

console.log(2 + 2);   // prints 4 — JS evaluates the expression first

// Use it constantly while learning. It's how you see what's happening.
```

## 3. Variables — Storing and Naming Data

A variable is a named container that holds a value. You give it a name, assign a value, and reference it by name later.

### `const` — Use This By Default

```javascript
const siteName = "Techium";
const maxUsers = 100;
const taxRate = 0.07;

/*
  const means the BINDING is constant — you cannot reassign the variable
  to point to a different value.
  This is the safest default: if something doesn't need to change, say so.
  Use const for ~90% of your variables.
*/

siteName = "Other"; // ❌ TypeError: Assignment to constant variable.
```

### `let` — Use When the Value Will Change

```javascript
let score = 0;
score = 10;    // ✅ reassignment is fine
score += 5;    // ✅ shorthand for score = score + 5
score++;       // ✅ shorthand for score = score + 1

let isLoggedIn = false;
isLoggedIn = true; // fine — the value genuinely changes

/*
  Use let when you know up front the value will be reassigned:
  counters, loop variables, state that changes over time.
*/
```

### `var` — Legacy. Understand It, Don't Use It.

```javascript
var oldThing = "I'm from 2010";

/*
  var predates const and let (introduced in ES6, 2015).
  It has confusing scoping rules (function-scoped, not block-scoped)
  and allows redeclaration, which leads to hard-to-find bugs.

  You WILL encounter var in legacy codebases — knowing it exists
  helps you read old code. But write new code with const and let.
  The difference that matters most:
*/

// var leaks out of blocks:
if (true) {
  var leaked = "I exist outside this block";
  let contained = "I stay inside this block";
}
console.log(leaked);    // "I exist outside this block" — surprise!
console.log(contained); // ❌ ReferenceError — behaves as expected

/*
  let and const respect block scope (anything inside {}).
  var does not. This is one of the biggest sources of bugs in older JS.
*/
```

### Naming Rules and Conventions

```javascript
// ✅ Valid and professional
const firstName = "Ana";         // camelCase — standard for JS variables
const userAge = 30;
const isActive = true;
const MAX_RETRIES = 3;            // SCREAMING_SNAKE_CASE for true constants

// ❌ Invalid — will throw a syntax error
const 1stName = "Ana";   // cannot start with a digit
const first-name = "Ana"; // hyphens not allowed — use camelCase
const class = "web";      // reserved keyword

// ❌ Valid but terrible
const x = "Ana";          // tells you nothing
const data = 30;          // vague
const flag = true;        // meaningless

/*
  Names should communicate intent. If someone reads your variable name
  and immediately understands what it holds, you've named it well.
*/
```

## 4. Data Types — The Kinds of Values JavaScript Understands

JavaScript has several built-in types. You need to understand each one because they behave differently and support different operations.

### Number

```javascript
const age = 25;          // integer
const price = 19.99;     // float (decimal)
const temperature = -5;  // negative
const big = 1_000_000;   // underscore for readability (ES2021)

// All arithmetic operators work on numbers
console.log(10 + 3);   // 13   addition
console.log(10 - 3);   // 7    subtraction
console.log(10 * 3);   // 30   multiplication
console.log(10 / 3);   // 3.333... division (always returns float if not even)
console.log(10 % 3);   // 1    modulo — the REMAINDER after division
console.log(10 ** 3);  // 1000 exponentiation (10 to the power of 3)

/*
  Modulo (%) is worth memorizing — it's used constantly:
  - Is a number even?  n % 2 === 0
  - Wrap around a range: index % array.length
  - Every Nth item in a loop: i % N === 0
*/
```

### String

A string is any sequence of characters wrapped in quotes.

```javascript
const name = "Ana";            // double quotes
const city = 'San Juan';       // single quotes — same thing
const sentence = `Hello!`;     // backtick (template literal)

// Concatenation — joining strings with +
const greeting = "Hello, " + name + "!";
console.log(greeting); // "Hello, Ana!"

// Template literals — embed expressions directly (preferred)
const betterGreeting = `Hello, ${name}! You're from ${city}.`;
console.log(betterGreeting); // "Hello, Ana! You're from San Juan."
/*
  Template literals use backticks and ${expression}.
  Anything inside ${} is evaluated as JavaScript — not just variables,
  but any expression: ${2 + 2}, ${user.name.toUpperCase()}, etc.
  Prefer template literals over + concatenation. They're cleaner.
*/

// Common string methods
const text = "JavaScript is powerful";
console.log(text.length);           // 22 — number of characters
console.log(text.toUpperCase());    // "JAVASCRIPT IS POWERFUL"
console.log(text.toLowerCase());    // "javascript is powerful"
console.log(text.includes("power")); // true
console.log(text.slice(0, 10));     // "JavaScript" — characters 0 through 9
console.log(text.replace("powerful", "awesome")); // "JavaScript is awesome"
console.log("  trim me  ".trim()); // "trim me" — removes leading/trailing whitespace
```

### Boolean

```javascript
const isActive = true;
const isLoggedIn = false;
/*
  Booleans have exactly two values: true or false.
  They are the result of comparisons and conditions.
  Named variables should read like yes/no questions:
  isValid, hasPermission, canEdit, isEmpty
*/

// Comparison operators always return booleans
console.log(10 > 5);    // true
console.log(10 < 5);    // false
console.log(10 >= 10);  // true
console.log(10 <= 9);   // false

// Equality — this is critical to understand
console.log(10 === 10);   // true  — strict equality (value AND type must match)
console.log(10 === "10"); // false — number vs string
console.log(10 !== 5);    // true  — strict inequality

console.log(10 == "10");  // true  — loose equality (type coercion, AVOID THIS)
/*
  Always use === (triple equals) and !== for comparisons.
  == performs type coercion — it converts types to make them match,
  which produces surprising results:
    0 == false   → true
    "" == false  → true
    null == undefined → true
  These are bugs waiting to happen. Use === to compare value AND type.
*/
```

### null and undefined

```javascript
let username;
console.log(username); // undefined
/*
  undefined means a variable was declared but never assigned a value.
  JavaScript sets it automatically. You rarely set it yourself.
*/

let selectedItem = null;
/*
  null means "intentionally empty" — the variable exists,
  it just currently has no value by your choice.
  Use null to signal "nothing here yet" in your own code.

  Key distinction:
  undefined = JavaScript says "no value was given"
  null       = You say "there is intentionally no value here"
*/
```

### Checking Type with `typeof`

```javascript
console.log(typeof 42);           // "number"
console.log(typeof "hello");      // "string"
console.log(typeof true);         // "boolean"
console.log(typeof undefined);    // "undefined"
console.log(typeof null);         // "object" ← famous historical bug in JS
console.log(typeof [1, 2, 3]);    // "object" ← arrays are objects
console.log(typeof function(){}); // "function"
```

## 5. Arrays — Ordered Collections

An array is an ordered list of values. Each item has a numeric index starting at 0.

```javascript
const fruits = ["apple", "banana", "orange"];
//               index 0    index 1    index 2

// Accessing items — zero-indexed
console.log(fruits[0]); // "apple"
console.log(fruits[1]); // "banana"
console.log(fruits[2]); // "orange"
console.log(fruits[3]); // undefined — index doesn't exist

// Length — number of items
console.log(fruits.length); // 3
// Last item (works regardless of array size):
console.log(fruits[fruits.length - 1]); // "orange"

// Modifying arrays
fruits.push("mango");      // add to END   → ["apple","banana","orange","mango"]
fruits.pop();              // remove from END → removes "mango"
fruits.unshift("grape");   // add to START → ["grape","apple","banana","orange"]
fruits.shift();            // remove from START → removes "grape"

// Check if something is in an array
console.log(fruits.includes("banana")); // true
console.log(fruits.includes("kiwi"));   // false

// Find the position of an item
console.log(fruits.indexOf("orange")); // 2 (or -1 if not found)

/*
  Arrays can hold mixed types: [1, "hello", true, null]
  But in practice, keep arrays homogeneous (all the same type).
  Mixed-type arrays are confusing to work with.
*/
```

## 6. Objects — Named Collections of Properties

An object stores data as **key: value** pairs. Unlike arrays (ordered by index), objects are organized by meaningful names.

```javascript
const person = {
  name: "Ana",
  age: 28,
  city: "San Juan",
  isStudent: true
};

/*
  Each key is a property name.
  Values can be any data type — including arrays and other objects.
  This is the fundamental data structure for representing real-world entities.
*/

// Accessing properties — two ways
console.log(person.name);       // "Ana"     — dot notation (preferred)
console.log(person["age"]);     // 28        — bracket notation

/*
  Use dot notation when the key name is known ahead of time.
  Use bracket notation when the key name is a variable:
*/
const prop = "city";
console.log(person[prop]); // "San Juan" — dot notation won't work here

// Adding and modifying properties
person.email = "ana@techium.com"; // adds new property
person.age = 29;                  // updates existing property

// Checking if a property exists
console.log("name" in person);           // true
console.log("phone" in person);          // false
console.log(person.hasOwnProperty("age")); // true

// Removing a property
delete person.isStudent;

// Nested objects (objects inside objects)
const company = {
  name: "Techium",
  address: {
    city: "San Juan",
    country: "Puerto Rico"
  },
  employees: ["Ana", "Carlos", "María"]
};

console.log(company.address.city);       // "San Juan"
console.log(company.employees[0]);       // "Ana"
```

## 7. Operators — Working With Values

### Arithmetic Operators

```javascript
let a = 10, b = 3;

console.log(a + b);   // 13    addition
console.log(a - b);   // 7     subtraction
console.log(a * b);   // 30    multiplication
console.log(a / b);   // 3.333 division
console.log(a % b);   // 1     modulo (remainder)
console.log(a ** b);  // 1000  exponentiation

// Shorthand assignment operators
let score = 100;
score += 10;  // score = score + 10  → 110
score -= 5;   // score = score - 5   → 105
score *= 2;   // score = score * 2   → 210
score /= 3;   // score = score / 3   → 70
score %= 9;   // score = score % 9   → 7

// Increment and decrement
let count = 5;
count++;  // post-increment: use value (5), then increment → count is now 6
++count;  // pre-increment: increment first, then use → count is now 7
count--;  // post-decrement: use value (7), then decrement → count is now 6
```

### Logical Operators

```javascript
/*
  Logical operators combine or modify boolean conditions.
  They're what makes decision-making code expressive.
*/

// AND (&&) — both conditions must be true
const age = 20;
const hasMembership = true;
console.log(age >= 18 && hasMembership); // true — both are true

// OR (||) — at least one condition must be true
const isAdmin = false;
const isModerator = true;
console.log(isAdmin || isModerator); // true — one is true

// NOT (!) — flips the boolean
console.log(!true);  // false
console.log(!false); // true

const isLoggedIn = false;
if (!isLoggedIn) {
  console.log("Please log in."); // runs because !false = true
}
```

## 8. Conditionals — Making Decisions

Conditionals let your code take different paths based on whether a condition is true or false.

### `if / else if / else`

```javascript
const score = 85;

if (score >= 90) {
  // This block runs ONLY if score >= 90
  console.log("Grade: A");
} else if (score >= 80) {
  // This block runs ONLY if score < 90 AND score >= 80
  console.log("Grade: B");
} else if (score >= 70) {
  // This block runs ONLY if score < 80 AND score >= 70
  console.log("Grade: C");
} else {
  // This block runs if NONE of the above conditions were true
  console.log("Grade: F");
}

/*
  The chain evaluates TOP TO BOTTOM.
  The FIRST true condition wins — its block runs, the rest are skipped.
  else is the fallback — it only runs if everything above was false.
*/
```

### Combining Conditions with `&&` and `||`

```javascript
const user = {
  name: "Carlos",
  age: 22,
  isPremium: true
};

if (user.age >= 18 && user.isPremium) {
  console.log(`Welcome ${user.name}! Premium access granted.`);
} else if (user.age >= 18) {
  console.log(`Welcome ${user.name}. Basic access.`);
} else {
  console.log("Access denied. Must be 18 or older.");
}
```

### The Ternary Operator — Compact Conditionals

```javascript
/*
  Syntax: condition ? valueIfTrue : valueIfFalse
  Use for simple assignments, not for complex logic.
*/

const age = 20;
const access = age >= 18 ? "full access" : "restricted access";
console.log(access); // "full access"

// Same as:
let access2;
if (age >= 18) {
  access2 = "full access";
} else {
  access2 = "restricted access";
}
```

## 9. Loops — Repeating Actions

### `for` Loop — When You Know the Count

```javascript
/*
  Anatomy: for (initialization; condition; update)
  - initialization: runs once before the loop starts
  - condition: checked before EVERY iteration — loop stops when false
  - update: runs after EVERY iteration
*/

for (let i = 0; i < 5; i++) {
  console.log("Iteration:", i);
}
// Output: 0, 1, 2, 3, 4
// Loop stops when i < 5 becomes false (when i === 5)

// Iterating through an array by index
const colors = ["red", "green", "blue"];
for (let i = 0; i < colors.length; i++) {
  console.log(`Color ${i}: ${colors[i]}`);
}
/*
  colors.length is 3.
  i goes: 0 → 1 → 2 → then i < 3 is false, loop exits.
  Access: colors[0], colors[1], colors[2]
*/
```

### `for...of` — Cleaner Array Iteration

```javascript
/*
  for...of gives you the VALUE directly on each iteration.
  No index variable needed. Cleaner when you don't need the index.
*/

const fruits = ["apple", "banana", "orange"];

for (const fruit of fruits) {
  console.log("I like", fruit);
}
// Output: I like apple / I like banana / I like orange

/*
  Use for...of when:
    - You need each value and don't care about the index
  Use the classic for loop when:
    - You need the index number (i)
    - You're building a new array based on position
    - You need to iterate in reverse or by steps
*/
```

### `while` Loop — When the Count Is Unknown

```javascript
/*
  while runs as long as the condition remains true.
  Use when you don't know in advance how many iterations you need.
*/

let attempts = 0;
const MAX_ATTEMPTS = 3;

while (attempts < MAX_ATTEMPTS) {
  const password = prompt("Enter password:"); // blocks until user types
  attempts++;

  if (password === "secret123") {
    console.log("Access granted!");
    break; // exit the loop immediately
  }

  const remaining = MAX_ATTEMPTS - attempts;
  if (remaining > 0) {
    console.log(`Wrong. ${remaining} attempt(s) left.`);
  } else {
    console.log("Access denied.");
  }
}
/*
  break exits the loop immediately — the rest of the body is skipped
  and execution continues after the closing brace.
  Always ensure your while condition can become false — an infinite
  loop will freeze the browser tab.
*/
```

### `break` and `continue`

```javascript
// break — exit the loop entirely
for (let i = 0; i < 10; i++) {
  if (i === 5) break; // stop at 5
  console.log(i);     // prints 0, 1, 2, 3, 4
}

// continue — skip this iteration, go to the next one
for (let i = 0; i < 10; i++) {
  if (i % 2 === 0) continue; // skip even numbers
  console.log(i);             // prints 1, 3, 5, 7, 9
}
```

## 10. Functions — Reusable, Named Logic

A function is a named block of code you write once and call whenever you need it. Functions are how you avoid repetition and organize your program into meaningful units.

### Declaring a Function

```javascript
/*
  function keyword + name + parameters + body
  This DEFINES the function — it doesn't run yet.
  It runs when you CALL it.
*/

function greet(name) {
  console.log(`Hello, ${name}!`);
}

// Call (invoke) the function:
greet("Ana");    // Hello, Ana!
greet("Carlos"); // Hello, Carlos!
/*
  One function definition, called with different inputs.
  This is the core value of functions: write once, run many times.
*/
```

### Parameters vs Arguments

```javascript
/*
  Parameter: the variable name in the function definition
  Argument:  the actual value you pass when calling it

  function add(a, b) { ... }
                ↑  ↑
            parameters (placeholders)

  add(5, 3)
      ↑  ↑
   arguments (real values)
*/

function add(a, b) {
  return a + b; // return sends a value BACK to the caller
}

const result = add(5, 3); // result = 8
console.log(result);      // 8

/*
  return exits the function immediately and sends back a value.
  Code after return in the same block never runs.
  If a function has no return, it implicitly returns undefined.
*/
```

### Default Parameters

```javascript
function greet(name = "stranger", greeting = "Hello") {
  return `${greeting}, ${name}!`;
}

console.log(greet("Ana"));            // "Hello, Ana!"
console.log(greet("Carlos", "Hola")); // "Hola, Carlos!"
console.log(greet());                 // "Hello, stranger!"
/*
  Default parameters are used when the argument is not provided (undefined).
  They make functions more flexible without requiring every argument every time.
*/
```

### The Early Return Pattern

```javascript
/*
  Instead of deeply nested if/else, return early when something is wrong.
  Each early return handles one failure case. The happy path goes last.
  This keeps functions flat and readable.
*/

function processOrder(user, items) {
  if (!user) {
    return "Error: no user provided."; // ← early return
  }

  if (!items || items.length === 0) {
    return "Error: no items in order."; // ← early return
  }

  if (!user.isPremium && items.length > 10) {
    return "Error: non-premium users cannot order more than 10 items.";
  }

  // If we reach here, everything is valid
  const total = items.reduce((sum, item) => sum + item.price, 0);
  return `Order placed! Total: $${total.toFixed(2)}`;
}
```

### Arrow Functions — Compact Function Syntax

```javascript
/*
  Arrow functions are a shorter syntax introduced in ES6.
  They're equivalent to regular functions for most purposes.
*/

// Regular function
function square(n) {
  return n * n;
}

// Arrow function equivalent
const square = (n) => {
  return n * n;
};

// Even shorter — if the body is a single return expression:
const square = (n) => n * n;  // implicit return — no braces, no return keyword

// With no parameters:
const sayHi = () => console.log("Hi!");

// With multiple parameters:
const add = (a, b) => a + b;

console.log(square(5));  // 25
console.log(add(3, 4));  // 7
```

## 11. Scope — Where Variables Live

Scope is the rule that determines which code can *see* a given variable.

```javascript
/*
  JavaScript has three levels of scope:
  1. Global — declared outside any function or block, visible everywhere
  2. Function — declared inside a function, visible only in that function
  3. Block — declared inside {} with let/const, visible only in that block
*/

const globalConfig = "I'm visible everywhere"; // global scope

function processUser() {
  const userId = 42; // function scope — only exists inside processUser()

  if (true) {
    const blockVar = "only in this if block"; // block scope
    console.log(userId);      // ✅ can see function scope from inner block
    console.log(globalConfig); // ✅ can see global scope from anywhere
    console.log(blockVar);     // ✅ within its own block
  }

  // console.log(blockVar); // ❌ ReferenceError — blockVar is gone
}

processUser();
// console.log(userId); // ❌ ReferenceError — userId is gone
```

### Why Scope Matters

```javascript
/*
  Scope protects your variables. Without it, every function would
  potentially see and modify every other function's variables.

  The narrower the scope, the less chance of accidental modification.
  Prefer const (can't be reassigned) in the narrowest scope possible.

  Global variables are a last resort. They're accessible everywhere —
  which also means they can be modified from everywhere, making bugs
  harder to trace.
*/

// Problem: global state is shared and mutable
let counter = 0; // global

function increment() { counter++; }
function reset()     { counter = 0; }

// Better: counter lives inside the function that owns it
function createCounter() {
  let count = 0; // private to this function's scope
  return {
    increment: () => ++count,
    reset:     () => { count = 0; },
    value:     () => count
  };
}
```

## 12. Variable Declarations — `var` vs `let` vs `const` Deep Dive

Now that you understand scope, the differences become meaningful.

```javascript
// =====================
// SCOPE
// =====================

function scopeDemo() {
  if (true) {
    var  x = "var";    // function-scoped — leaks out of this block
    let  y = "let";    // block-scoped — stays inside
    const z = "const"; // block-scoped — stays inside
  }
  console.log(x); // "var"   ← leaked out
  console.log(y); // ❌ ReferenceError
  console.log(z); // ❌ ReferenceError
}


// =====================
// HOISTING
// =====================

/*
  Hoisting: variable DECLARATIONS are moved to the top of their
  scope before code runs. But assignments stay in place.
*/

console.log(a); // undefined (declaration was hoisted, value was not)
var a = 5;

console.log(b); // ❌ ReferenceError: Cannot access 'b' before initialization
let b = 5;
/*
  With var, hoisting "works" but produces undefined — confusing.
  With let/const, you get a clear ReferenceError — better.
  This is called the Temporal Dead Zone: let/const exist in scope
  but cannot be accessed before their declaration line.
*/


// =====================
// CONST WITH OBJECTS
// =====================

const user = { name: "Ana", age: 28 };
user.age = 29;           // ✅ modifying a property — fine
user.city = "San Juan";  // ✅ adding a property — fine
// user = { name: "Ana" }; // ❌ reassigning the variable — not allowed

/*
  const locks the BINDING (the variable's reference) not the VALUE.
  The object itself is still mutable — you can change its properties.
  What you cannot do is point the variable at a different object.
  Same applies to arrays: const arr = []; arr.push(1) is fine.
*/
```

### The Decision Rule

```
Default → const
Need to reassign? → let
Working with legacy code? → var (read only, don't write new var)
```

## 13. The DOM — Making Pages Interactive

The **DOM (Document Object Model)** is the browser's internal representation of your HTML as a tree of JavaScript objects. Every HTML element becomes a JavaScript object you can read and modify.

```
HTML:                         DOM tree:
<body>                        document
  <header>                      └── body
    <h1>Hello</h1>                    ├── header
  </header>                    │         └── h1 "Hello"
  <main>                              └── main
    <p>Welcome</p>                         └── p "Welcome"
  </main>
</body>
```

### Selecting Elements

```javascript
/*
  querySelector() — returns the FIRST element matching a CSS selector
  querySelectorAll() — returns ALL matching elements (a NodeList)

  These accept any valid CSS selector: element, .class, #id, and combos.
  Use these. The older getElementById/getElementsByClassName still work
  but querySelector is more flexible.
*/

const title   = document.querySelector("h1");          // first h1
const navLink = document.querySelector("nav a");       // first link in nav
const card    = document.querySelector(".card");       // first .card
const hero    = document.querySelector("#hero");       // element with id="hero"

const allButtons = document.querySelectorAll("button"); // NodeList of ALL buttons
const allCards   = document.querySelectorAll(".card");  // NodeList of ALL .cards

// Iterate over querySelectorAll results
allButtons.forEach(button => {
  console.log(button.textContent);
});
```

### Reading and Changing Content

```javascript
const heading = document.querySelector("h1");

// Read content
console.log(heading.textContent); // raw text — no HTML tags
console.log(heading.innerHTML);   // HTML string — includes any tags inside

// Write content
heading.textContent = "Welcome to Techium";
/*
  Always prefer textContent over innerHTML when inserting plain text.
  innerHTML parses its value as HTML — if it contains user input, that's
  an XSS (Cross-Site Scripting) security vulnerability.
  textContent treats everything as literal text, never as HTML.
*/

heading.innerHTML = "<em>Welcome</em> to Techium"; // only when you need HTML
```

### Changing Styles and Classes

```javascript
const box = document.querySelector(".card");

// Direct style (use sparingly — better to toggle classes)
box.style.backgroundColor = "red";
box.style.fontSize = "24px";        // camelCase — not font-size
box.style.display = "none";         // hide element

/*
  Directly setting style properties creates inline styles — they're hard
  to override and mix CSS into your JavaScript.
  The better pattern: define states in CSS classes, then toggle classes.
*/

// classList — the right way to manage visual state
box.classList.add("active");         // add a class
box.classList.remove("hidden");      // remove a class
box.classList.toggle("selected");    // add if missing, remove if present
box.classList.contains("active");    // returns true/false
```

### Changing Attributes

```javascript
const link = document.querySelector("a");
const img  = document.querySelector("img");

console.log(link.getAttribute("href")); // get any attribute value
link.setAttribute("href", "https://techium.com"); // set any attribute
link.setAttribute("target", "_blank");

img.setAttribute("src", "images/new-photo.jpg");
img.setAttribute("alt", "Updated photo description");
```

### Responding to Events

An **event** is something that happens in the browser: a click, a key press, a form submission, the page finishing its load.

`addEventListener()` registers a function to run when an event occurs on an element.

```javascript
/*
  element.addEventListener("eventName", callbackFunction)
  The callback runs every time the event fires on that element.
*/

const button = document.querySelector("#submit-btn");

button.addEventListener("click", function(event) {
  /*
    event is the Event object — it contains info about what happened.
    event.target is the element that was clicked.
    You can call it whatever you want: event, e, ev — e is common.
  */
  console.log("Button clicked!", event.target);
});

// Arrow function — same thing, shorter:
button.addEventListener("click", (e) => {
  console.log("Clicked!", e.target.textContent);
});

// Common event types:
// "click"       — user clicks an element
// "input"       — user types in a text field (fires on every keystroke)
// "change"      — user changes a select or checkbox
// "submit"      — user submits a form
// "mouseover"   — mouse enters element
// "mouseout"    — mouse leaves element
// "keydown"     — user presses a key
// "DOMContentLoaded" — HTML is fully parsed and DOM is ready
```

## 14. Putting It All Together — Interactive Counter

This example combines DOM selection, events, functions, conditionals, and template literals:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Counter App</title>
  <style>
    body        { font-family: Arial, sans-serif; padding: 2rem; }
    #display    { font-size: 3rem; font-weight: bold; margin: 1rem 0; }
    #display.positive { color: green; }
    #display.negative { color: red; }
    button      { padding: 0.8rem 1.6rem; font-size: 1rem; margin: 0.4rem; cursor: pointer; }
  </style>
</head>
<body>

  <h1>Counter</h1>
  <p id="display">0</p>
  <button id="btn-increase">+ Increase</button>
  <button id="btn-decrease">− Decrease</button>
  <button id="btn-reset">Reset</button>

  <script>
    // State — the single source of truth for our counter's value
    let count = 0;

    // DOM references — select once, reuse many times
    const display    = document.querySelector("#display");
    const btnIncrease = document.querySelector("#btn-increase");
    const btnDecrease = document.querySelector("#btn-decrease");
    const btnReset    = document.querySelector("#btn-reset");

    // Update function — all display changes go through here
    function updateDisplay() {
      display.textContent = count;

      // Reflect sign in CSS class (defined in <style> above)
      display.classList.remove("positive", "negative"); // clear current state
      if (count > 0) display.classList.add("positive");
      if (count < 0) display.classList.add("negative");
      /*
        This pattern — clear state classes, then set the correct one —
        is a standard approach to managing visual state with JS.
      */
    }

    // Event listeners — one per button
    btnIncrease.addEventListener("click", () => {
      count++;
      updateDisplay();
    });

    btnDecrease.addEventListener("click", () => {
      count--;
      updateDisplay();
    });

    btnReset.addEventListener("click", () => {
      count = 0;
      updateDisplay();
    });

    // Run once on load so the display is initialized
    updateDisplay();
  </script>

</body>
</html>
```

## 15. Reading Error Messages — Debugging

JavaScript errors appear in the browser console. Learning to read them is a fundamental skill.

### The Three Most Common Error Types

```javascript
// 1. ReferenceError — you used a variable that doesn't exist
console.log(userName); // ReferenceError: userName is not defined
/*
  Check spelling. Check scope — was it declared in this scope?
  If using let/const, was it accessed before declaration?
*/


// 2. TypeError — you called something that isn't callable,
//    or tried to access a property on undefined/null
const user = null;
console.log(user.name); // TypeError: Cannot read properties of null
/*
  This is the most common runtime error.
  It means you expected an object but got null or undefined.
  Add a guard: if (user) { console.log(user.name); }
*/

const text = 42;
text.toUpperCase(); // TypeError: text.toUpperCase is not a function
/*
  You called a string method on a number.
  typeof user — checking the type before calling methods saves pain.
*/


// 3. SyntaxError — your code isn't valid JavaScript at all
function broken( {  // SyntaxError: Unexpected token '{'
  return 1;
}
/*
  The file won't run at all — syntax errors are caught before execution.
  Look for: missing closing brackets/braces/parentheses,
  missing commas in objects/arrays, typos in keywords.
*/
```

### Using `console.log()` to Debug

```javascript
function calculateTotal(price, quantity, taxRate) {
  // Log inputs first — verify what the function actually received
  console.log("calculateTotal called with:", { price, quantity, taxRate });

  const subtotal = price * quantity;
  console.log("subtotal:", subtotal); // verify intermediate step

  const tax = subtotal * taxRate;
  console.log("tax:", tax);

  const total = subtotal + tax;
  console.log("total:", total);

  return total;
}

/*
  When debugging: trace the data through your function step by step.
  Wrong output? Log inputs → log each calculation → find the step that goes wrong.
  When the bug is fixed, remove the debug logs before committing.
*/
```

### DevTools Breakpoints (More Powerful Than `console.log`)

1. Open DevTools → **Sources** tab
2. Find your script file in the file tree
3. Click any line number to set a **breakpoint** — a red dot appears
4. Reload the page — execution *pauses* at the breakpoint
5. Inspect any variable's value by hovering over it or checking the right panel
6. Press the **Step Over** button (F10) to execute one line at a time

This lets you *walk through* your code as it runs — far more powerful than scattering `console.log()` everywhere.

## 16. Common Mistakes and How to Avoid Them

```javascript
// ❌ Mistake 1: Using = instead of === in conditions
let x = 10;
if (x = 5) { // ASSIGNS 5 to x and evaluates as true — always runs!
  console.log("This always runs");
}
// ✅ Fix:
if (x === 5) { // COMPARES x to 5
  console.log("Only runs if x is 5");
}


// ❌ Mistake 2: Accessing a property before checking if the object exists
function displayUserName(user) {
  console.log(user.name); // TypeError if user is null or undefined
}
// ✅ Fix:
function displayUserName(user) {
  if (!user) return; // guard clause
  console.log(user.name);
}


// ❌ Mistake 3: Forgetting that array indices start at 0
const items = ["a", "b", "c"];
console.log(items[3]); // undefined — there is no index 3 (only 0, 1, 2)
// ✅ Fix:
console.log(items[items.length - 1]); // "c" — always gets the last item


// ❌ Mistake 4: Mutating an array you're iterating over
const nums = [1, 2, 3, 4, 5];
for (let i = 0; i < nums.length; i++) {
  nums.splice(i, 1); // modifying the array mid-loop — skips items
}
// ✅ Fix: iterate over a copy, or build a new array instead


// ❌ Mistake 5: Using == instead of ===
console.log(0 == false);   // true  ← type coercion surprises
console.log("" == false);  // true  ← type coercion surprises
// ✅ Fix: always use === for comparisons


// ❌ Mistake 6: Not handling the case where querySelector returns null
const btn = document.querySelector("#nonexistent-button");
btn.addEventListener("click", () => {}); // TypeError: Cannot read properties of null
// ✅ Fix:
const btn = document.querySelector("#nonexistent-button");
if (btn) {
  btn.addEventListener("click", () => {});
}
```

## 17. Best Practices — Writing Professional JavaScript

```javascript
// 1. Prefer const. Use let only when reassignment is necessary.
const API_URL = "https://api.techium.com"; // never changes
let currentPage = 1;                        // will be incremented

// 2. Write descriptive names. Names should answer: "what does this hold?"
const u = getUserById(3);           // ❌ what is u?
const currentUser = getUserById(3); // ✅ obvious

const arr = [10, 20, 30];           // ❌ arr of what?
const monthlyRevenue = [10, 20, 30]; // ✅ clear

// 3. Each function does one thing
// ❌ Too many responsibilities in one function
function processAndDisplayAndSaveUser(data) {
  // validates, transforms, renders, and persists — all in one place
}

// ✅ One responsibility per function
function validateUser(data) { /* ... */ }
function renderUserCard(user) { /* ... */ }
function saveUser(user) { /* ... */ }

// 4. Comment the WHY, not the WHAT
// ❌ Useless — the code already says this
let i = 0; // set i to 0

// ✅ Explains a non-obvious reason
const DEBOUNCE_MS = 300;
// 300ms chosen to balance responsiveness with avoiding excess API calls
// Anything faster triggers rate limiting on the search endpoint

// 5. Select DOM elements once and store the reference
// ❌ Querying the DOM on every click is slow
button.addEventListener("click", () => {
  document.querySelector("#status").textContent = "Clicked"; // queries every click
});

// ✅ Query once, reuse the reference
const status = document.querySelector("#status");
button.addEventListener("click", () => {
  status.textContent = "Clicked"; // fast
});
```

## Quick Reference

| Concept | Key Point |
|---|---|
| `const` | Can't reassign — use by default |
| `let` | Can reassign — use when value changes |
| `var` | Function-scoped, hoisted — avoid in new code |
| `===` vs `==` | Always use `===` — strict comparison, no type coercion |
| `typeof` | Returns a string: `"number"`, `"string"`, `"boolean"`, `"object"`, `"undefined"`, `"function"` |
| Template literal | Backticks + `${expression}` — prefer over string concatenation |
| `null` | Intentional absence of value — you set this |
| `undefined` | Unintentional absence — JS sets this automatically |
| Array index | Zero-based — first item is `[0]`, last is `[length - 1]` |
| `forEach` | Iterates array; `for...of` also works — prefer over classic `for` when index not needed |
| `querySelector` | First matching element; `querySelectorAll` for all matches |
| `textContent` | Safe — treats input as plain text; `innerHTML` — parses as HTML (XSS risk) |
| `addEventListener` | `element.addEventListener("eventName", callback)` |
| Scope | `const`/`let` are block-scoped; variables can't be seen outside the `{}` they're declared in |
