02

What is NodeJS?

NodeJS is a runtime environment — it's the engine that executes JavaScript code outside of a web browser. The key distinction for students is this shift:

Before Node

JavaScript → Browser only

With Node

JavaScript → Operating System

NodeJS is built on three pillars:

Chrome V8 engine

The same JavaScript engine used in Google Chrome. It compiles JS directly to machine code, making Node fast.

Event-driven architecture

Node waits for events (user input, file ready, HTTP request) and reacts. Nothing blocks while waiting.

Non-blocking I/O

Disk reads, network requests, and database queries run in the background. Node keeps processing other work in the meantime.

Analogy Think of a waiter in a restaurant. A blocking waiter would stand at your table watching your food cook. A non-blocking waiter takes your order, goes to help other tables, and comes back when your food is ready. NodeJS is the non-blocking waiter.
03

Why NodeJS?

Before Node, if you wanted to build a server-side application in JavaScript, you couldn't. You had to switch to a different language entirely (PHP, Python, Java, Ruby). Node changed that by giving JS access to system-level capabilities:

  • Create web servers and APIs
  • Read and write files on disk
  • Access environment variables and OS processes
  • Interact with databases
  • Handle real-time networking (WebSockets)
  • Build command-line tools

This is why fullstack JavaScript became possible. One language across the entire stack: React on the frontend, Node on the backend, the same syntax and mental model throughout.

04

First execution — modules and exports (Task 0)

The first task seems trivial — print a message — but its real purpose is teaching the Node module system. Every concept here will repeat throughout the entire project.

// 0-console.js
function displayMessage(message) {
  console.log(message);
}

module.exports = displayMessage;
Key concept: module.exports In the browser, scripts share scope automatically. In Node, each file is its own isolated module. Nothing leaves a file unless you explicitly export it with module.exports. Without it, require('./0-console') returns an empty object — the function simply doesn't exist outside the file. 
// 0-main.js
const displayMessage = require('./0-console');
displayMessage('Hello, Holberton!');

require() reads the file at the given path, executes it, and returns whatever was assigned to module.exports. The ./ prefix tells Node to look in the current directory — without it, Node searches node_modules for a package instead.

Flow visualization
0-main.js runs
↓
require('./0-console') is called
↓
Node executes 0-console.js
↓
module.exports returns displayMessage function
↓
displayMessage('Hello') → console.log prints to STDOUT

STDOUT (Standard Output) is simply where text output goes — usually the terminal. console.log() writes to STDOUT by default.

Three beginner mistakes to pre-empt in class:

  • Forgetting module.exports entirely. The file runs but nothing is returned — the require call gets {}.
  • Wrong require path: require('0-console') tells Node to look in node_modules. Always use require('./0-console') for local files.
  • Calling the function on export: module.exports = displayMessage() exports the return value (undefined) instead of the function itself. No parentheses when exporting.
05

Understanding process.stdin (Task 1)

process is a global object Node gives you for free — no require needed. It represents the currently running Node program and exposes three important I/O streams:

process.stdin

Standard Input — keyboard input from the user (or piped data)

process.stdout

Standard Output — where text you print goes (usually the terminal)

process.stderr

Standard Error — for error messages, shown separately from normal output

process.stdout.write('Welcome to Holberton School, what is your name?\n');

process.stdin.on('data', (data) => {
  process.stdout.write(`Your name is: ${data}`);
});

process.stdin.on('end', () => {
  process.stdout.write('This important software is now closing\n');
});
Key concept: event-driven programming process.stdin.on('data', callback) does not wait — it registers a listener and returns immediately. Node continues running other code. When data actually arrives (the user types something), Node fires the callback. This is the event loop in action. The callback runs later, not now.
Flow visualization
Program starts → prompt is printed
↓
Node registers listeners and enters the event loop
↓
User types → 'data' event fires → callback executes
↓
User presses Ctrl+D → 'end' event fires → program closes

This pattern — register a listener, do nothing until the event arrives, react when it does — is the foundation of servers, APIs, WebSockets, and databases in Node. Everything that comes later in this project builds on this exact idea.

Reading files with fs — synchronous (Task 2)

The fs (filesystem) module is a built-in Node module for working with files. Unlike process, it must be required explicitly:

const fs = require('fs');

Synchronous (blocking)

const data = fs.readFileSync(path, 'utf8');
// Nothing else runs until
// the file is fully read.

Asynchronous (non-blocking)

fs.readFile(path, 'utf8', (err, data) => {
  // runs later, when ready
});
Why UTF-8 matters Without specifying encoding, fs.readFileSync(path) returns a raw Buffer object like <Buffer 66 69 72 73 74...>. Passing 'utf8' as the second argument tells Node to decode the bytes into a human-readable string.

In Task 2, students parse a CSV file. Walk them through the strategy step by step so the array methods feel purposeful, not magical:

Read the file → get one long string
↓
data.split('\n') → array of lines
↓
.filter(line => line.trim() !== '') → remove trailing empty lines
↓
Skip index 0 (header row: firstname, lastname, age, field)
↓
line.split(',') on each row → array of fields
↓
Group students into an object: { CS: [], SWE: [] }
Teaching moment: why an object? Ask students: why use students['CS'] instead of two separate arrays? An object lets you look up any field value dynamically — students[field] — without writing a separate branch for each possible value. This is a real pattern they'll use again.
07

Async file reading and Promises (Task 3)

Task 3 rewrites Task 2 using asynchronous code. This is arguably the most conceptually dense part of the project. Take extra time here.

Why async matters for servers Imagine 1,000 users connecting simultaneously. A synchronous server reads each file one at a time, making every other user wait. An async server kicks off all 1,000 reads at once and responds to each as it finishes. This is what makes Node scalable.

A Promise is an object that represents a value that isn't available yet. It's always in one of three states:

Pending

The operation is in progress. Neither success nor failure has happened yet.

Resolved (fulfilled)

The operation succeeded. resolve(value) was called. The .then() handler fires.

Rejected

The operation failed. reject(error) was called. The .catch() handler fires.

function countStudents(path) {
  return new Promise((resolve, reject) => {
    fs.readFile(path, 'utf8', (err, data) => {
      if (err) {
        reject(new Error('Cannot load the database'));
      } else {
        // parse data, then:
        resolve();
      }
    });
  });
}

// Caller:
countStudents('./database.csv')
  .then(() => { /* success */ })
  .catch((err) => { console.error(err.message); });
Most common mistake: forgetting return The function must return new Promise(...). Without the return, the caller gets undefined instead of a Promise — .then() crashes with "Cannot read property of undefined."

.then() means "when the async operation succeeds, run this code." .catch() means "if anything goes wrong anywhere in the chain, run this code instead." They can be chained — .then().then().catch() — each step receiving the result of the previous one.

08

HTTP servers (Task 4)

This is where backend development truly begins. A server is a program that listens for incoming requests and sends back responses. The HTTP module is built into Node — no install needed.

const http = require('http');

const app = http.createServer((req, res) => {
  res.end('Hello Holberton School!');
});

app.listen(1245);
module.exports = app;

req (request)

Represents the incoming request from the browser. Contains req.url (the path), req.method (GET, POST…), and req.headers.

res (response)

The object you use to send data back. res.end() closes the connection. res.write() sends data without closing. Call res.end() exactly once per request.

What is a port? A port is like a numbered door into your computer. Port 80 is the default for web traffic, 443 for HTTPS. In development we use non-privileged ports like 1245 or 3000. localhost:1245 means: "connect to my own machine through door 1245."
Test with curl 
curl localhost:1245
This sends a real HTTP GET request from the terminal. Students can watch the server respond without opening a browser.

Advanced HTTP server (Task 5)

Task 5 combines routing, async file reading, and server logic together. The core principle students must internalize is separation of concerns — different URLs trigger different behaviors:

const app = http.createServer((req, res) => {
  if (req.url === '/') {
    res.end('Hello Holberton School!');
  } else if (req.url === '/students') {
    countStudents(DATABASE)
      .then((data) => {
        res.end(data);
      })
      .catch(() => {
        res.end('Cannot load the database');
      });
  }
});
The backend mental model Every backend request follows the same shape: Request → Logic → Response. The URL tells you which logic to run. The logic does work (reads a file, queries a DB). The response sends the result back. This pattern never changes, no matter how complex the framework.

ExpressJS (Task 6)

Express is a minimal web framework for Node. It doesn't add new capabilities — it wraps Node's built-in http module and makes common tasks dramatically cleaner. Install it with:

npm install express

Raw Node HTTP

if (req.url === '/' &&
    req.method === 'GET') {
  res.writeHead(200);
  res.end('Hello');
}

Express

app.get('/', (req, res) => {
  res.send('Hello');
});

Express handles HTTP method matching, content-type headers, and status codes automatically. A basic Express server:

const express = require('express');
const app = express();

app.get('/', (req, res) => {
  res.send('Hello Holberton School!');
});

app.listen(1245);
module.exports = app;
package.json When you run npm install express, two things happen: the library is downloaded into node_modules/, and package.json is updated with a dependency entry. package.json is the project's blueprint — it lists every external library the project needs so anyone can recreate the environment with npm install. Never manually edit node_modules/.

Advanced Express routing (Task 7)

Task 7 introduces REST-style URLs and proper HTTP status codes. Two concepts to nail:

REST resource URLs

GET /            → homepage
GET /students    → all students
GET /students/CS → CS students

URLs represent resources, not actions. The HTTP method (GET, POST, DELETE) expresses the action.

HTTP status codes

200 → OK, success
404 → Not found
500 → Server error

Always send the appropriate status. res.status(500).send('Cannot load the database') — clients use status codes to decide how to handle the response.

Full server architecture (Task 8)

This is the most important task in the entire project. Students stop writing everything in one file and start organizing like professional backend developers.

Why does architecture matter? Imagine a codebase with 10,000 lines in a single file — no one could maintain it. Professional projects split responsibilities across files so that each piece is small, testable, and replaceable. This is the separation of concerns principle. 
full_server/
├── controllers/
│   ├── AppController.js      ← homepage logic
│   └── StudentsController.js ← student route logic
├── routes/
│   └── index.js              ← URL → controller mapping
├── utils.js                  ← shared helpers (readDatabase)
└── server.js                 ← entry point, starts the server
FileAnalogyResponsibility
server.jsReceptionistStarts the app, wires everything together. Entry point only — no business logic here.
routes/index.jsBuilding directoryMaps every URL to the controller that handles it. router.get('/students', StudentsController.getAllStudents)
controllers/Office workersContains the actual logic — what to do when a route is matched. One controller per resource.
utils.jsTools roomReusable helper functions like readDatabase(). Logic that multiple controllers share lives here.
database.csvFiling cabinetThe data. In a real app this is a database. Here it's a CSV file.

Dynamic route parameters let one route handle many values:

// Route definition
router.get('/students/:major', StudentsController.getAllStudentsByMajor);

// Inside the controller
const { major } = req.params;

if (major !== 'CS' && major !== 'SWE') {
  return res.status(500).send('Student not found');
}
Express Router express.Router() creates a mini-app that handles a group of routes. In large projects you might have one router for /users, one for /products, one for /orders, each in its own file. They're combined in server.js with app.use(router).

ES6 + Babel

Modern JavaScript (ES6+) introduced cleaner syntax for imports, exports, arrow functions, and more. Babel is a transpiler — it converts modern JS into older, universally compatible JS before Node runs it.

ES6 (modern)

import express from 'express';

export default app;

CommonJS (Node default)

const express = require('express');

module.exports = app;

Both do the same thing. Babel allows students to write ES6 syntax and have it automatically compiled to CommonJS before execution. This is relevant because most modern Node projects and all React projects use ES6 module syntax.

14

Nodemon

Every time you change your server code, you have to stop and restart the server manually. Nodemon watches your files for changes and restarts automatically — a significant quality-of-life improvement during development.

Without Nodemon

Edit code
↓
Ctrl+C to stop server
↓
node server.js again
↓
Test change
↓
Repeat for every edit

With Nodemon

npm run dev (once)
↓
Edit code
↓
Server restarts automatically
↓
Test change immediately

The scripts section in package.json lets you define shortcuts so npm run dev runs whatever long nodemon command is needed, without typing it each time.

Core concepts students must understand

Non-blocking I/O

Node does not pause execution waiting for slow operations (disk, network). It registers a callback and moves on. This is why Node can handle thousands of concurrent connections on a single thread.

Event-driven programming

Code doesn't run top-to-bottom in sequence. Instead, functions run in response to events: data arrived, file read, HTTP request received. The event loop orchestrates all of this.

Request/response cycle

Every web interaction is a request (browser asks) and a response (server answers). Understanding this cycle is the foundation of all backend development.

Separation of concerns

Each file should have one job. Routes map URLs to handlers. Controllers contain logic. Utils contain helpers. When concerns are separated, bugs are easier to find and code is easier to change.

Common student errors

  • Forgetting return before new Promise(). The promise is created but the caller receives undefined. Add return: return new Promise(...).
  • Forgetting module.exports. Code runs fine in isolation but nothing is importable. Every file that exports something must end with module.exports = ....
  • Using synchronous file reading in an async context. Using readFileSync inside a Promise or async route handler blocks the entire server. Use readFile (async) instead.
  • Sending multiple responses. Calling res.send() or res.end() twice on the same response throws an error. Each request gets exactly one response.
  • Missing or wrong status codes. Always use res.status(500).send(...) for errors — not just res.send(...) — so clients can detect failures.
  • Not handling errors in promises. An unhandled rejected Promise will crash the server in newer versions of Node. Always chain .catch().
  • Wrong path to the database. The path passed to readFile is relative to where node is run from, not where the file is. Use the argument passed in, not a hardcoded relative path.
